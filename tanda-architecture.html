Tanda — Lead Intake Architecture

Go worker | Supabase | LM Studio | Gmail API | Lovable Admin

Worker Responsibilities

  • • Poll Gmail for new inbound inquiries
  • • Deduplicate by Gmail message ID
  • • Call LM Studio to extract structured lead data
  • • Write leads + threads + drafts to Supabase
  • • Send approved drafts + task notifications via Gmail
  • • No HTTP API — admin UI is separate

Database Schema

  • • leads — email, intent, confidence, status
  • • email_threads — Gmail thread linkage
  • • draft_responses — approval flow + send state
  • • tasks — assignable follow-ups
  • • All migrations via Supabase SQL Editor
  • • Managed by Lovable (not liquibase/go)
  • • Access via pgxpool (direct Postgres)

Admin UI (Lovable)

  • • React/Next.js frontend
  • • Talks directly to Supabase (no backend)
  • • Lead queue, approval flow, detail view
  • • Approve drafts in DB — worker sends Gmail
  • • Mutations via Supabase client SDK
  • • Auth handled by Supabase Auth

AI / LLM

  • • Model: qwen/qwen3.6-35b-a3b
  • • Endpoint: http://[LM-STUDIO-HOST]:1234/v1
  • • OpenAI-compatible REST API
  • • Timeout: 10 minutes (slow local)
  • • Extracts: intent, dance_style, level, confidence

Key Files

  • • cmd/worker/main.go — entry point
  • • internal/ingest/ingest.go — core logic
  • • internal/gmail/service.go — polling
  • • internal/ai/ — LM Studio client + prompts
  • • internal/db/pool.go — Postgres pool

Environment

  • • OPENAI_BASE_URL=http://[LM-STUDIO-HOST]:1234/v1
  • • OPENAI_API_KEY=dummy / lm-studio
  • • DATABASE_URL — Supabase pooler
  • • Gmail OAuth2 via credentials.json + token.json
  • • .gitignore guards all secrets
